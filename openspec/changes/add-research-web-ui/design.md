# Design

## Context

The API contract and generated types come from `add-research-api`:

- `GET /api/research/stream` sends `stage`, `partial`, `narrative`, `error` and `report` events.
- A later `partial` with the same key replaces the earlier one. Comps arrive twice: first without `peer_rationales`,
  then with them, after the narrative has started.
- A cached report arrives as two validation `stage` events and one `report` event, with no partials.
- Report sections that failed are `StageError` objects (`kind: "error"`, `stage`, `message`).
- `frontend/src/lib/types.ts` is generated by `npm run gen:types`; event payloads are untyped there
  (`data: {[key: string]: unknown}`).

The component list is in IMPLEMENTATION_PLAN.md §7. The UI must look good in a live demo on a laptop screen and stay
usable on a phone. The frontend is Next.js 16 (App Router, Turbopack, React 19 with the React Compiler, Tailwind v4).

## Goals / Non-Goals

**Goals:**
- One custom hook owns the `EventSource`; a pure reducer turns events into report state; components are
  presentational.
- No global state library; everything derives from the hook's state.

**Non-Goals:**
- User accounts, saved watchlists, report history beyond the 1-hour cache.
- Server-side rendering of report data (the stream is client-side).

## Decisions

- **Next.js 16 App Router:**
  - `app/page.tsx` renders a client `TickerForm`.
  - `app/report/[ticker]/page.tsx` is a Server Component that awaits `params` (synchronous access is removed in
    Next.js 16) and renders the client `ReportView` with the upper-cased ticker. Nothing else runs on the server.
- **`lib/events.ts`** types the event payloads by hand on top of the generated schemas: `StageEvent`,
  `PartialEvent` (a union keyed by `key`: `snapshot`, `financials`, `comps`, `risks`, `news`, `scorecard`,
  `analyst`), `NarrativeEvent`, `ErrorEvent`, `ReportEvent`, plus `isStageError()`.
- **`lib/reportState.ts`** holds the pure reducer and its state:
  - `stages`: per step, `pending | running | done | failed | skipped`, with `ms` and `cached`;
  - `sections`: the latest value per partial key, or a section error;
  - `narrative`: the accumulated text; `report`; `fatal` (terminal error); `unreachable`.
  - A partial replaces its section; the `report` event replaces every section from the report and sets the
    narrative to `narrative_markdown`. When the report arrives, steps still pending become `skipped`, or `cached`
    when the report came from the cache.
  - `reset` starts over (refresh and retry).
- **`useResearchStream(ticker, nonce, refresh)`:**
  - opens `new EventSource(`${API_URL}/api/research/stream?ticker=...&refresh=...`)` with a listener per event name;
  - dispatches parsed events to the reducer;
  - closes on `report` or terminal `error`, so the browser never reconnects and starts another run;
  - treats `onerror` before any event as "backend unreachable" and closes; an error after events have arrived but
    before a final event is shown as a connection loss with the same retry;
  - `API_URL` comes from `NEXT_PUBLIC_API_URL` (inlined at build time) and defaults to `http://localhost:8000`.
- **Agent cards** map stage names to labels: `financials` → Financial data, `comps` → Comps, `comps_explain` → Peer
  rationales, `risk` → Risk, `news` → News, `analyst` → Analyst, `writer` → Writer. Validation is shown in the page
  header, not as a card. The card shows the model when the report's usage records name one.
- **Formatting helpers** in `lib/format.ts` mirror the backend's `formatting.py`: percent metrics as "27.6%",
  debt-to-equity with two decimals, other multiples with one, non-positive valuation multiples as missing,
  compact currency (`$4.82T`) and "—" for null. They are covered by unit tests (Vitest).
- **Charts:**
  - Recharts line chart of daily closes, downsampled to weekly points on the client;
  - a bar chart of the primary multiple for the target vs peers, with the median reference line.
  Each chart has a visually hidden summary sentence.
- **Narrative:** `react-markdown` on the accumulated text, without raw HTML. The four headings come from the Writer's
  format.
- **Styling:** Tailwind v4 with a small token set (neutral surfaces; signal colours green/amber/red, always paired
  with text labels), light and dark themes. Use the `frontend-design` skill for the visual direction.
- **Testing:**
  - Vitest with jsdom and React Testing Library for the formatting helpers, the reducer and the components.
  - Fixtures are real event sequences, not hand-written: `backend/scripts/export_ui_fixtures.py` runs the pipeline on
    recorded data with FakeClaude and writes `frontend/src/test/fixtures/*.json` (AAPL fresh, AAPL cached, JPM,
    an unknown ticker and AAPL with the risk agent failing).
  - Manual check of the full demo flow against the live backend.

## Risks / Trade-offs

- [`EventSource` reconnects automatically on network blips and could replay events] → The reducer is idempotent: a
  replayed partial replaces its section, and the API replays from the start for late subscribers. The narrative is
  the one accumulating field, so a reconnect resets state before replaying.
- [Recharts bundle size] → Acceptable for a local demo; loaded only on the report page.
- [Hand-written event payload types can drift from the backend] → They are built from the generated schema types,
  and the reducer tests run against fixtures exported from the real pipeline.
