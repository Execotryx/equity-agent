# Repository guide

This is the Autonomous Equity Research Agent capstone: a Python FastAPI backend and a Next.js/React frontend.
Read `README.md`, `IMPLEMENTATION_PLAN.md`, and the relevant change under `openspec/changes/` before changing behavior.

## Architecture

- `backend/src/equity_agent/models.py`: shared Pydantic data contracts. Missing values are `None`; percentages are fractions.
- `data/`: Yahoo, SEC EDGAR and Tavily adapters. `cache.py` owns SQLite persistence and TTLs.
- `scoring.py`: deterministic arithmetic, peer eligibility and signal scoring. Models do not calculate financial figures.
- `agents/`: compact evidence payloads, Markdown prompts, output validation and one bounded re-ask.
- `pipeline.py`: shared CLI, evaluation and API report execution, concurrent branches and degradation.
- `streaming.py`: a registry of independently pumped runs, replayed to SSE subscribers.
- `frontend/src/lib/`: generated schema types, event contracts, report reducer and stream hook.
- `backend/tests/fixtures/`: recorded providers; `tests/fakes.py` supplies offline model outputs. `backend/demo/` is a separate recording.

Paths in the backend entries above are relative to `backend/src/equity_agent/` unless stated otherwise.

## Behavioral invariants

- Normalize tickers before cache access. An unexpired report must be served without contacting providers; Refresh bypasses it.
- Refresh the SEC latest-filing lookup. Parsed filing content and valid risk selections remain reusable for an unchanged accession.
- Treat only EDGAR's `CompanyNotFoundError` as an absent company. Provider failures must not be cached as missing filings.
- Evaluate every fallback candidate. Worker concurrency and the number of eligible peers shown are separate limits.
  Recheck cached peer choices against current eligibility; replace a choice that no longer supplies enough valid peers.
- Validate generated and cached risk selections against their source headings. Require six distinct headings, nonempty text,
  verbatim references, prompt word limits and descending severity. Analyst validation must agree with its prompt too.
- Number grounding preserves signs, including Unicode minus and currency prefixes. It is a diagnostic token-presence
  check; it does not prove that prose assigns a value to the correct metric or uses its units correctly.
- Keep the SSE names `stage`, `partial`, `narrative`, `error`, `report`. A recoverable application `error` is a
  `MessageEvent`, and must not be mistaken for EventSource's transport error. Terminal events close the stream.
- Treat malformed JSON as a controlled stream failure and ignore callbacks from a closed or superseded stream.
- Derive final progress failures from report sections, including cached reports; cache reuse does not imply success.
- Subscriber disconnects stop their subscription; the registry's pump continues to cache the report. Shutdown stops
  accepting runs and cancels model work once. Drain owned tasks, background explanations and already-running provider
  threads before closing shared services. Python thread cancellation cannot interrupt a provider call already running.
- Keep prompts, API models, frontend types and event fixtures consistent. Do not edit generated types manually.
- Never print API keys or environment-file contents. Keep deterministic tests offline and preserve fixture/golden evidence.

## Verification

From `backend/`, run `uv run pytest` and `uv run pyright`. Always run Pyright after Python changes if available;
if unavailable, try `uv add pyright`. On Windows an existing environment can also be checked directly with
`.venv/Scripts/python.exe -m pytest` and `.venv/Scripts/pyright.exe`.

From `frontend/`, run `npm test`, `npm run lint`, `npx tsc --noEmit --incremental false`, and `npm run build` as
appropriate. If Windows denies access to Vitest fork workers (`EPERM`), retry with
`npm test -- --pool=threads --maxWorkers=1` and record the limitation. Hook regressions must exercise EventSource
event dispatch and cleanup, rather than only feeding events directly to the reducer.

Read the relevant guide under `frontend/node_modules/next/dist/docs/` before frontend changes, as required by
`frontend/AGENTS.md`. Follow those instructions and the local package versions.

If payload schemas change, run root `npm run gen:types`; if event semantics change, review fixtures generated by
`backend/scripts/export_ui_fixtures.py`. Golden regeneration is intentional: inspect differences and use
`UPDATE_GOLDEN=1` only when the changed behavior warrants it. Live tests use `RUN_LIVE_TESTS=1` and spend credits;
they are separate from the normal offline gates.

The KASE matrix is in `backend/tests/kase_cases.py`. Run its offline identity regressions with
`uv run pytest tests/test_kase_cases.py`. Execute the live matrix from `backend/` with
`RUN_LIVE_TESTS=1 uv run pytest -m live tests/test_kase_live.py -q -s` (PowerShell: set
`$env:RUN_LIVE_TESTS = '1'` first). Six native probes use Yahoo; three full reports use Claude and Tavily.
Each execution creates `docs/kase-dd-MM-yyyy-HH-mm-ss/` with Markdown/JSON results and complete report evidence.
Native cases require the named issuer, KZT currency and a KASE venue. A Nasdaq `KSPI` quote must not count as
the KASE ordinary share. KASE Global cases deliberately use US listing inputs (`AAPL`, `NVDA`, `JPM`);
their reports do not validate KASE quotes or automatic routing of `_KZ` symbols. Missing native coverage remains
a failed live acceptance case, not an expected failure. Recheck the linked exchange instrument lists when
updating this matrix. Keep these observations separate from the normal offline gates.

For USD-traded instruments, run `RUN_LIVE_TESTS=1 uv run pytest -m live tests/test_kase_usd_live.py -q -s`.
This matrix has five native USD probes (`HSBKd`, `KSPId`, `KZAPd`, `FRHC_KZ`, `CORE_KZ`) and two separate
US-listing report cases (`KSPI`, `FRHC`). Evidence is saved to `docs/kase-usd-dd-MM-yyyy-HH-mm-ss/`.
Preserve the `d` suffix identifying depositary receipts; uppercasing must not remove it or substitute the
KZT ordinary share. USD currency alone does not identify a KASE venue. Native probes pass through the app's
ticker normalization, so unsupported underscore symbols fail at validation before provider access. Declare
the original KASE symbol and actual research input separately; keep the correct source URL for each listing.

Check the final diff for whitespace, using a CRLF-aware check for existing CRLF files. Preserve existing line endings
and unrelated edits. Run `cargo check` after any Rust changes and fix its errors.

## Change records and local environment

- Record changes and their reasoning in `docs/` (create it if absent). Use a separate Markdown record whose creation
  timestamp follows `dd-MM-yyyy-HH-mm-ss`; dates and times use the client's Asia/Qyzylorda timezone.
- Update this guide and/or applicable `CLAUDE.md` whenever a feature introduces new workflows or invariants.
- If local Ollama is needed, run `ollama ls`; prefer an installed `lfm2.5-thinking`, otherwise another installed LFM model.
- Docker is available through WSL on Ubuntu. The app's normal local setup does not require containers.
