# KASE company test cases

Creation: 10-10-2026-21-10-06 (Asia/Qyzylorda).

The task is to create several cases for companies available on KASE and execute them against the application.
The official [KASE instrument list](https://kase.kz/en/investors/instruments/shares) and
[KASE Global list](https://kase.kz/en/markets/kase-global) were checked on 10 October 2026.
The catalog stores company identities and listing symbols, without asserting fixed market prices.

## Changes and reasoning

- Added `backend/tests/kase_cases.py`: six Kazakhstan issuers and three KASE Global companies, with explicit
  input symbols, expected currency, company name and trading venue. The catalog is test data and does not
  introduce automatic exchange routing into the application.
- Added `backend/tests/test_kase_cases.py`: offline regressions reject another exchange's quote, a matching
  currency without a matching venue, an unrelated issuer and an unknown venue. Explicit US listings remain
  separate from KASE symbols. These checks prevent a successful Yahoo response from disguising missing coverage.
- Added `backend/tests/test_kase_live.py`: opt-in native quote acceptance probes and complete live reports for
  three KASE Global companies. Full reports use fresh in-memory caches and `refresh=True`, exercising real
  Yahoo, SEC, Tavily and Claude calls without altering the app's persistent research cache or offline recordings.
- Each live run saves timestamped Markdown and JSON evidence under `docs/`, including complete reports,
  acceptance checks, model usage/cost, timings and quality warnings. Missing native coverage fails visibly.
- Updated `AGENTS.md` with execution instructions and the distinction between native KASE instruments and
  US listings of companies available through KASE Global.

Native probes require a positive equity quote for the correct issuer, ticker, currency and venue. US-listing
reports additionally use the existing acceptance criteria for financials, peers, reasoned signal, risks and
disclaimer, and require a writer narrative. Performance budgets are recorded separately from structural pass/fail.
These tests do not assess investment suitability or prove factual correctness of every generated sentence.

## Reproduction

From `backend/`, in PowerShell:

```powershell
.venv/Scripts/python.exe -m pytest tests/test_kase_cases.py -q
.venv/Scripts/pyright.exe
$env:RUN_LIVE_TESTS = '1'
.venv/Scripts/python.exe -m pytest -m live tests/test_kase_live.py -q -s --tb=short
```

The live suite requires the existing backend configuration with `DEMO_OFFLINE` disabled. Native probes need
no model credentials; full report cases require the normal Claude, Tavily and EDGAR settings and spend credits.
Normal pytest runs deselect these live cases. Six native failures are possible while offline regressions pass:
they represent missing data coverage, not a reason to weaken the instrument-identity criteria.

## Verification

- Offline identity regressions: 7 passed. Full offline backend suite: 287 passed, 11 live cases deselected.
- Pyright: 0 errors, 0 warnings.
- Live matrix: **3 passed, 6 failed**, in 74.35 seconds. Native KASE coverage failed for all six cases.
  HSBK, KZAP, KMGZ, KEGC and KCEL returned `ticker not found`. KSPI resolved to Kaspi.kz on NasdaqGS in USD,
  failing both KZT currency and KASE venue criteria. These cases were executed, not skipped or marked xfail.
- Apple, NVIDIA and JPMorgan passed structural full-report acceptance using their US listings, within the
  existing performance budgets. Recorded Claude cost was **$0.2103** in total, with 12 model calls;
  Tavily credits were also used but are not measured by the report's cost field.
- All three reports had `SEC filing unavailable (TypeError)` rather than extracted filing risks. Existing
  acceptance criteria permit this degradation when it has a reason. The pass result does not mean SEC
  retrieval succeeded. The provider/runtime error remains visible in each saved report.
- Apple produced a 452-word narrative against a 450-word limit. NVIDIA produced a 468-word narrative and
  flagged numeric tokens `62`, `58`, `65` absent from its writer input. JPMorgan had no narrative quality
  warnings. These diagnostics are preserved and do not count as structural acceptance failures.
- Evidence: [live results](kase-10-10-2026-21-10-01/results.md) and
  [machine-readable results](kase-10-10-2026-21-10-01/results.json), plus one JSON per case with complete
  reports for the US-listing cases. The Markdown summary was expanded from this captured data to display
  costs and degradation explicitly; no additional paid reports were run for that presentation change.

Native KASE research therefore remains unsupported by the current Yahoo-based adapter for this matrix.
Automatic `_KZ` routing, a KASE data adapter and repairs to SEC retrieval were outside this test-case task.
